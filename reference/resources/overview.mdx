MCP Resources are static or cached data objects that your AI client reads passively at connection time — think of them as configuration files or reference tables your assistant consults silently in the background. Unlike Tools (which are callable functions that fire live API requests on demand), Resources give the AI the foundational context it needs to answer questions about supported chains, available tokens, and server health without incurring extra round-trips to external data providers.

## Available Resources

CryptoMCP exposes four built-in resources over the `cryptomcp://` URI scheme:

<CardGroup cols={2}>
  <Card title="cryptomcp://tokens" icon="coins">
    A complete list of every supported token, including display names, ticker symbols, and contract addresses across all chains.
  </Card>
  <Card title="cryptomcp://chains" icon="link">
    Supported blockchain networks and their configurations — chain IDs, RPC details, native currency symbols, and block explorer URLs.
  </Card>
  <Card title="cryptomcp://providers" icon="server">
    All configured data providers (e.g. CoinGecko, Etherscan, DefiLlama) along with their current health status and rate-limit headroom.
  </Card>
  <Card title="cryptomcp://version" icon="tag">
    The running CryptoMCP server version, build timestamp, and a manifest of every tool that was successfully loaded at startup.
  </Card>
</CardGroup>

## How Resources Are Accessed

Your MCP-aware AI client (Claude Desktop, Cursor, or any other compatible client) reads these resources automatically during the connection handshake. The AI uses the data to:

- Resolve token symbols and contract addresses before calling tools like `get_price` or `get_wallet_balance`
- Validate that a requested chain or provider is actually available before attempting a live query
- Surface accurate chain names and explorer links in formatted responses

You don't need to do anything special to trigger this — it happens in the background every time a session starts. That said, you can also prompt your AI directly to surface the data:

- *"List all supported chains."*
- *"What tokens does CryptoMCP support?"*
- *"Are all data providers online right now?"*

<Note>
  Resources are read once at client connection time and cached for the duration of the session. If you add a new chain, update a provider API key, or upgrade the server binary, **restart CryptoMCP** so clients pick up the refreshed resource data on their next connection.
</Note>
